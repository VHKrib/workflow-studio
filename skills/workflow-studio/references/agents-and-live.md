# Agent 分析、流式输出与实时画布

本文件说明调用边界与已知接口的核查方法；先确认当前分支的真实调用路径，不把历史函数名或上限当最新实现。语义与原始数据对照另读 `references/workflow-evidence.md`。

## 1. 分清分析与执行

- 一条工作流可指定执行方，流程级咨询与分析入口可能使用固定分析方；不要因改一个对话框而锁死整条产品线的执行方。
- 显示名、分组与可用性从数据取，不硬编码本机团队。保留字 profile 与显示名分开处理，默认分析方不在普通 profiles 目录也要能正确显示。
- 分析只给 `todo,no_mcp` 等当前明确批准的受限工具组；关闭 MCP 连接而非仅隐藏常规工具，防止被读 agent 自带接口越界。
- 只读预演使用零执行工具的受限组，并由主进程再次强制限制；不能把渲染层传参当唯一权限边界。
- 渲染层只走 preload 暴露的 IPC；不直接 require 文件系统或执行子进程。读他人会话用只读 SQLite，配置、技能和对话先脱敏，不读凭据文件。

## 2. 读取 agent 平时的链路

1. 读身份、职责、技能、实际工作样本、上下游和读写线索，保留其来源；不要以安装了某技能推断实际用过。
2. 按业务环节归纳卡片，而非按工具名称列操作。输入说清材料来源，加工说清具体方法，输出说清交付与接收对象；保留 mods 和 impl。
3. 把分析结果留在预览，完整解析后校验类型、空卡、引用、环与连通；结构校验通过不证明业务关系真实，必须与源证据对照。
4. 用户确认后才放进正式工作流；分析、预览和重试不能隐式落卡。被读对象与后续执行方的关系按当前产品约定明确赋值，不能由模型自行猜。
5. 有预算地收场；总时长、自动重试共用预算。超时或断流后清半成品、保留可理解的错误并可重来，不无限增加等待时间。

常用定位：`chain.js` 取只读原料，`main.js` 管 IPC 与子进程，渲染层的读取状态、解析、预览和放置函数负责用户确认。

## 3. 输出解析不能读到提问回显

- 优先使用 `--format stream-json` 的正式 result.text，不从混有提问回显、工具轨迹和会话尾部的整段 stdout 取第一个 JSON。
- 兼容文本输出时按实际格式拆正式回答与尾部信息；候选 JSON 从后往前查，并拒绝占位示例。协议改变时同步修改提示词、解析器和断言。
- JSON 被截断或字段丢失时明确报未拆全；不能用示例 JSON、合成答案或邻近节点补线伪装成功。
- 解析器不得默认清空模型给出的模块和内部实现；正文中的技术细节可保守搬到 impl，不因清洗破坏具体业务数字或要求。

## 4. 流式生命周期

典型路径是主进程 spawn → 逐事件转发 → preload 订阅 → 渲染层局部更新；以当前事件结构核对 tool_use、tool_result、text、result，不假设推理正文总会存在。

- 每次运行使用独立 runId；订阅在成功、失败、取消后都注销。收尾将 live 状态清掉，把未结束的工具标为中断，避免界面永远显示进行中。
- 最终无增量文本时，用完整 result.text 补回答；候选也从最终完整回答提取，不只看增量缓冲区。
- 原回答、工具轨迹、摘要、候选分别保留；展示人话不能覆盖原始正式回答。
- 逐帧只更新当前流消息，其他消息 DOM 不动；details 展开态和滚动不被重建清空。
- 取消要真终止子进程。换对象、关窗、Esc 和重来走同一取消路径，并用 token/active 标识丢弃旧事件；置 busy=false 而不停止后端不算取消。
- 将启动、最新进展和已等待时间分开记录；无新内容可显示仍在等待，但不能据此宣称进程一定健康或即将结束。

## 5. 独立实时画布

- 按明确选定会话读取增量，并按消息/调用身份去重；切会话重置该会话的状态，旧异步结果不能写进新画布。
- 打开跟随前先确认目标会话可选且快照属于它；停止跟随应停后台读取并保留图；画布现在是主窗口里的内嵌视图，收起视图不影响主窗口。
- 实时窗口只读，主进程拒绝其对正式工作流、共享底稿和版本文件的写入；前端没有按钮不等于硬边界成立。
- 机械动作映射只能作临时粗版。正式分析到达后粗版不得覆盖它；但新消息的读取游标与统计仍要推进，不能为了挡覆盖把实时更新整个停掉。
- **卡片口径以读取链路为准，不另造关系图。** 同一批 4–9 张输入/加工/输出卡、保留 mods/impl、加工卡三段（素材=上游卡模块 / 工具=本卡做法 / 成果=下游卡模块）由连线推导。版本卡、点评卡、分支边和状态徽标都是被用户否掉的方向，做出来只会整体回退。
- 取料用派活原文、真实步骤、读写文件、交付四样，核会话窗口和工具参数截断；没有读到不能判成没发生。同名不同来源不合并，但结论体现在正文与连线，不在卡面展示版本史。
- 解析只认 cards 非空的 JSON（围栏从后往前，再试首尾花括号）；过闸门（三类齐全、加工有进出边、整条连成一片）不合格就自动重拆一次，仍不合格报错并保留上一份有效结果；指向被滤掉卡的边丢掉。正文技术句搬进 impl，长正文按句号截断。
- 渲染按 edges 反推模块三段；跟随只推已解析的那份，旧图不得盖掉新结果，失败时明确标注是旧结果。
- **实时画布的卡片可以改、也可以拖，但只改这份解析结果。** 面板放**左边**、宽度行为和主画布一样（收起零宽、展开 364px、画布 flex 让位），双击卡片展开，里面直接渲染从 `paintPanel` 搬来的同一段模板：名字 / 类型 / 三色内容块 / 模块增删 / 内部实现·校验，**外加「和它聊这张卡」聊天区**（漏掉它用户会直接说「agent 也没有」）。聊天的「和谁聊」用 `conv.who`，发送走 `askAgent({profile: conv.profile, prompt})`，气泡按 `role: me/agent` 存进 `card.chat` 并随解析结果落盘；每次发送是一次真实模型调用，只由用户点发送/快捷问句触发。保存走一个独立 IPC 写回 `live/<profile>__<session>.json` 并立即重画，状态写「已保存（改过）」。它不改源会话、不改主画布链路、不进版本系统；「只读」的含义是不动别人的对话与主画布，不是不许改这张图。自动算出来的药丸→文件对应会配错，人得能直接改对，否则预览等于不可用。
- **拖动与位置持久化。** 画布卡片本来只能自动分列，用户会直接说「没法拖动」。按住卡片用 pointerdown/move/up 移动，坐标按缩放与滚动换算成画布坐标；松手后写回卡片的 `x/y` 并发一次保存。**layout 必须尊重手工坐标**：卡上有 `x/y` 就按它摆、不参与自动成列，否则一重排就弹回去；重载后位置还在才算做完。pointerdown 要先排除 `details` 和 `.mod`（否则点开折叠/悬停药丸被当成拖动），空白处仍走画板平移。拖动时给 `cursor:grabbing` 与抬升阴影，否则手感像卡住。
- **卡片、连线、拖动、排版都与主画布同源。** 源窗口的 `nodeEl` / `modsHTML` / `chipHTML` / `drawEdges` / `dragCard` / `layoutChain` 整段放在共享脚本 `renderer/cardsys.js`，两个页面各自主脚本之前引入；实时窗口只提供适配器：`flow()`（`{id, nodes: doc.cards, edges: doc.edges.map(e => [e[0], e[1]])}`，id 容错到 `doc.name || 'live'`）、`find()`、`saveStore()`、`openCard()`、`chatAsk()`、`markSel()`、`unplugDrag()`、`findDock()`（恒 null，实时不接插槽）、`startLink()`（只提示只读）。写完就在窗口里核三件事：`typeof nodeEl/layoutChain/dragCard` 都是 function、拖一张卡后 `x/y` 变了且落盘 `manual:true`、点「↗ 连线」只出提示不改边。
- **实时画布内嵌在主窗口里，是右栏列表的第一行，不再是独立窗口也不再是整窗浮层。** 结构：右栏 `renderWorkflowList` 前置一行「实时工作流」（虚线边、`liveMode` 时高亮、其它行让出选中），内容区 `.canvaswrap` 里放 `position:absolute; inset:0` 的视图容器 + `<webview>`，靠 `.canvaswrap.live` 显示并隐藏 `#wrap`/缩放条/dock/空态按钮。主进程 `webviewTag: true`；`<webview>` 的 `preload` 必须是绝对路径，而沙箱 preload 拿不到 `__dirname`，所以先 `await tcflow.appDir()`（走 `app:dir` IPC）再 `setAttribute('preload', dir + '/preload.js')`，最后才设 `src`；`dom-ready` 后把 `getWebContentsId()` 交给 `live:attach`，主进程用 `webContents.fromId(id)` 存成 `LIVE.wc`，`sendLive()` 改发 `LIVE.wc.send('live:doc', doc)`，并在 `destroyed` 时清空引用、停轮询。`live:open`/协议入口只做 `focusMain()` + `MAIN_WIN.webContents.send('live:show')`，渲染层收到再进入 live 模式——不再 `new BrowserWindow`。切走只是从画布区移开，视图、选中会话与解析结果都留着；主进程重启后视图要重新 attach 才会继续收增量。
- **渲染完必须对焦到卡片。** 卡在 `ORIGIN` 偏移后的坐标上，`fit()` 没跑就是 `scrollLeft=0` + 卡在 6000px 外，`nodes=8 / visible=0`，看起来全白；在 `requestAnimationFrame` 里二次 `fit()`，验收断言用「卡片 rect 与视口相交数」，不用卡片总数。

- 验收断言查内容层：加工卡模块行数、正文无路径/命令/JSON、卡片重叠 0、每条连线两端都在卡片集合里；只看节点数或 class 相同不算对齐。
- **悬停要给真内容，不是一行说明。** 能定位到真实文件就按类型渲染：图片直接出图（等比缩放）、视频出可播放的 player、文本/文档出可滚动的正文框；定位不到或读失败才退回文字明细。浮层的宽高都要夹在视口内（`min(420px, calc(100vw - 32px))` 这类），图片/视频是异步加载的，`load`/`loadedmetadata` 后必须按最后指针位置重新摆一次，否则会先摆好再被撑出窗口——这是用户实际报过的「图片溢出窗口」。只读文件走主进程一个 peek IPC（返回 `file://` 或前几千字文本），渲染层拿不到就不硬猜；页面 CSP 要放行 `img-src file:` 与 `media-src file:`。
- **文件路径不能只靠模型写。** 模型常把 impl 写成业务话，一句路径都没有：解析后要做一次机械回填——从工具调用参数与命令里收集**绝对路径**（只认 `/Users`、`/Applications`、`/Volumes`、`/tmp` 这类根），命令行里的裸文件名用最近一次 `cd` 的目录拼成绝对路径；chip 名对不上就退回该卡的第一份文件。正则只收绝对路径：宽松匹配会把 `xxx-v1/v2/v3.png` 抓成 `/v2/v3.png`，预览直接失效。**一张卡上常有好几份素材/成果，每个 chip 必须对应它自己那一份**：按 chip 名与文件名词/词干的重合度打分（命中词干加高分，卡内那句含该文件名再加分），并列时按出现顺序、同一行已用过的先跳过；再加反义词扣分（前/后、上/下、装配/落、左/右、素描/线稿、草图/线稿），否则「下落前线稿」会配到「线稿-下落后.png」。实在没有可匹配的才退回该卡第一份，但绝不能让整行都指向同一张。
- **解析结果要落盘，按钮要能「重新生成」。** 一次成功的解析按「岗位 + 会话」保存（用户数据目录下 `live/<profile>__<session>.json`，临时文件+改名），重开窗口、切回该会话时直接把保存的那份渲染出来（打开即看，不重跑模型）；有结果后按钮文案变「重新生成」，新的没拆成功就保留旧的，不拿半份覆盖。初始化时**跟随关着也要 hydrate 一次**：只在“跟随开启”分支里恢复，重开窗口会显示空画布。
- **改卡面/预览时重放保存的那份，不跑模型。** 渲染层留一个只读入口（如 `window.__renderDoc(doc)`）把 `live/<profile>__<session>.json` 直接摆上来，改样式、改药丸、改浮层都在它上面验；一次模型调用都不花。只有协议/取料变了、或用户点「重新生成」才真调——用户会明确抱怨「怎么老是要重跑链路，这不浪费时间么」。
- **「跟随」只负责读消息与更新状态，不自动解析。** 自动重解析会让每次打开窗口都白跑一次模型，用户看到的是「怎么又要重读」；解析只由按钮触发，空画布提示写「点解析链路开始」。
- **分析调用别污染对话列表。** 每次 `hermes chat -q` 都会新建一个会话（通常只有一问一答两条消息），它会排到「最近对话」最上面，用户可能把它当成真会话去解析。列表查询过滤 `message_count >= 3` 即可，不改会话库。
- **不要给 `hermes chat` 传自定义 `--source`。** 网关只认固定几种来源，写一个自造值会直接以退出码 1 结束，表现成「分析没跑完（1）」，整条解析失败；要区分自己的调用就用别的办法（过滤、标记等）。

## 6. 临时建链路与共享底稿

- 临时画布与正式列表分开，不把临时对话写成用户已固定的工作流；保存为正式必须明确确认。
- 若某入口用用户要求作起草占位，标明起草，正式卡回来时替换，不把该占位当真实输入素材。读取真实工作流时不制造要求卡作为素材。
- 流式卡只追加完整对象；最终用完整计划对齐，不留下半张卡。卡片出现时同步收掉空画布遮罩，遮罩可见与否不能只在整页 render 时更新。
- 只在新增卡看不见或被浮层挡住时调整视野，避免持续抢用户的平移与缩放；确认后进入正式列表、换新身份并清理临时状态。
- 主进程共享底稿采用临时文件加原子换名，检测自身写入避免循环同步；坏文件保持上一份有效状态。外部同步按稳定节点身份保留本机对话/检查/预演，不把它们暴露到结构文件里。
- agent 可读共享结构但不能通过工具改画布或底稿；提议必须留在确认层。所有发给 agent 的相关入口带当前结构和版本事实，不能只有某个聊天框知道。

## 7. 验证入口与注意事项

在当前仓库、独立端口和数据目录，用 `terminal` 按需执行已有脚本：

- `skills/workflow-studio/scripts/parse-agent-output.js`：核正式回答、思考/工具步骤与耗时的拆分；真实调用选项以脚本为准。
- `skills/workflow-studio/scripts/check-plan.js`、`check-fixtures.js`：协议与结构样本，不据样本反推业务规则。
- `skills/workflow-studio/scripts/cdp-read.js --agent <显式对象>`：预览、流、权限、确认落卡、取消与布局。
- `skills/workflow-studio/scripts/cdp-read-stability.js --agent <对象> --mode <脚本支持的模式>`：断流、超时、重来、停滞与真取消。
- `skills/workflow-studio/scripts/cdp-live.js`：临时画布、共享文件与确认保存；真实聊天选项与离线模式分开报告。
- `skills/workflow-studio/scripts/cdp-livewin.js`：独立窗、换会话、跟随与只读边界。`--setup` 只准作用于自有样本数据，先读脚本确认清理范围。
- `skills/workflow-studio/scripts/cdp-eval.js --port <端口> --page <live.html|index.html> --expr-file <文件>`：在已开窗口里跑一段表达式并打印结果；表达式写文件，避开 shell 对反引号、`${}`、引号的转义坑。内嵌视图在 CDP 目标是 `type: 'webview'`，过滤目标时别只认 `page`。

- **实时画布的界面/交互验收不用跑模型：造一份样张 doc。** 在隔离实例的数据目录下写 `live/<profile>__<session>.json`（结构：`conv{profile,session,who,title}` + `cards[{id,kind,title,body,impl,mods[{type,name,path}]}]` + `edges[[a,b]]`），会话 id 用列表里真实存在的一条，打开窗口就会 hydrate 出卡。预览（悬停出图/播放器/文本）、双击编辑、拖动与位置持久化、浮层是否出视口，全都能在这份样张上断言；写回、重载后位置还在也能当场验。只有协议、取料或提示词变了才真调一次模型。

开第二窗口或长分析时，若 CDP 等待跨窗口 IPC 挂起，先用 fire-and-forget 发起，再从独立调用核窗口/运行结果；不能把空 evaluate 回执当异步已完成。所有截图、原始响应和断言与同一个代码版本绑定。
