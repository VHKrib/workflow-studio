# 工作流开发平台

维护同一产品的业务卡片、画布、agent 分析、实时展示和版本协作。先验证用户认可的业务效果，再做最小实现与独立验证；不代执行被观察的业务流程。

## When to Use

- 修改输入/加工/输出卡、交互、模块、连线、对话或分析协议。
- 排查读取 agent 与实时工作流的卡片差异、素材复用与输出归属，或把实时入口对齐到用户认可的那套卡。
- 维护临时画布、共享结构、编辑版本、回滚、复制、预演与公开交付。
- 不用于授权付费生成、外发业务内容或改其他岗位的数据与配置。

## 始终适用的边界

- **先核当前授权与工作树。** 主管仅有方案/收口职责时，不代写产品代码或代验收。派工与直接实现由当前授权决定，不以历史偏好覆盖岗位边界。
- **同一工作树一个写者。** 用户要求并行时，把独立测试、源证据或边界清楚的模块分到独立副本；主卡保留唯一集成写者，支线结果在最终代码上复核。
- **不连接、关闭或重启用户的 9222 窗口。** 实现/验收/收口分别使用 9333/9334/9335 和各自数据目录；停实例先核 PID、命令与 cwd，不用宽泛 pkill。
- **读取他人记录只读且先脱敏。** 不读凭据、不写会话库；不因分析需要修改其他岗位配置或业务素材。
- **不靠新按钮补默认行为。** 该默认说人话、正确归类、过滤闲聊、保留输出、适应窄窗的，默认做对。
- **保护现有工作。** 不全局 git add 混收并行改动，不 reset/删未跟踪文件腾地方；用户叫停后保留原状，不补测、提交、合并或发布。
- **公开内容只属本产品。** 真实业务对话、商品、岗位/部门名、本机路径、凭据及其截图只放私有证据位置；不进入代码、文档、图片或符号链接目标。
- **完成必须有对应版本的证据。** 独立用例交付、解析成功或一张待验截图不等于产品验收通过；之后的解析/布局修改会使相关旧证据失效。

## 卡片与分析的统一口径

1. **一张卡代表业务环节，不是消息或工具调用。** 输入是实际调用的材料/文件；加工是采用的方法；输出是真正交付的产物。用户要求、寒暄和系统通知不是输入素材。
2. **两种入口用同一种业务卡。** 读取 agent 展示平时主线，实时展示本次实例；范围可不同，标题、正文、素材/工具/成果与内部实现的含义必须相同。相同 CSS 不能证明统一。
3. **卡面人话且具体。** 说清哪些图/数据、怎样挑比改、产物包含什么；不用处理数据、跑命令等泛称。路径、命令、字段与证据标识进 impl，业务数字和版本信息不能被粗暴删掉。
4. **保留 mods/impl，并让模块可悬停查明细。** 加工卡同时显示来源素材、自身做法/工具和真实成果；上下游模块从关系推导。正文切片不是模块，缺字段不能伪造。鼠标移到素材/成果上要能看出「它是什么 · 来自哪张卡 · 具体路径/参数」，用跟随指针的浮层，不用原生 `title`；能定位到真实文件时直接预览内容（图片出图、视频出播放器、文本出可滚动正文），浮层与媒体都夹在窗口内。**同一张卡上每个药丸对应它自己那份文件**（按名字/词干打分、同行去重、反义词扣分）；全部指向第一张等于没做，用户一眼就看出来。
5. **两种入口是同一套卡，不加版本卡、点评卡或分支层。** 用户对「读取链路 vs 实时」的最终口径是「以读取为准」：同样 4–9 张输入/加工/输出、同样保留 mods/impl、同样连线规则。反馈与换做法从正文和真实连线读得出来，不是新卡种、新边标签或版本徽标。
6. **材料身份分得清是取料要求，不是卡面结构。** 同名不同来源、同路径重写不能合并成一个事实；文本提及和回读检查不算新的业务使用。分清是为了不画错，不是为了在卡上展示版本史。
7. **正文写「用什么素材 → 怎么做 → 交出什么」。** 加工卡只写「做了什么」不算说清；路径、命令、文件名的句子搬进 impl，业务数字（字节、时间点、版本号）要保留；长正文按句号截断，不硬切半句。
8. **质量闸 + 一次自动重拆。** 三类卡齐全、每张加工卡有入边和出边、整条连成一片才算数；不合格自动再拆一次（最多两次），仍不合格如实报错并保留上一份有效结果，不把错图画上画布。模型给的连线指向被过滤掉的卡时直接丢弃，不留悬空线。
9. **最新不等于采用。** 较新的版本、主干或实线样式都不能代替用户明确确认。
10. **先查取料，再改模型提示。** 核目标会话、范围、正文/工具参数/结果截断与 JSON 解码；没读到不能称没发生。固定卡数和文件计数不能替代语义验证。

## Procedure

### 1. 固定最小目标与基线

用 `terminal` 核 git status、branch、最近提交与写者；用 `read_file` 和 `search_files` 追实际入口，不凭手册猜当前文件/API。

选一份用户认可的真实样张，对照取料 → 提示词 → 解析对象 → IPC → 展示，先找丢失的业务含义或字段。只改失配处，不自动升级为通用引擎重写。补充要求即使仍在同一主卡，也要判断范围和估时是否变化。

完成标志：最小预期图、需保留的行为、实际失配层明确。原始数据与语义核查按 `references/workflow-evidence.md`。

### 2. 依当前职责实现或派工

- IPC 变更核主进程、preload、前端三端；渲染层不直接访问文件系统或起进程。
- 分析禁止执行原业务；核实际工具组并关闭 MCP，不能只靠提示词说只读。
- agent 提议先预览，用户明确确认才进入正式画布；只读实时窗口不得绕过主进程写入权限。
- 取消要真停后端、退订事件并丢弃旧结果；不能只清 busy。换对象、关窗、重来和超时遵循同一生命周期。
- 编辑不重建输入面板；单击选中、双击详情、空白拖动平移，主画布卡上不直接编辑（改字走左栏）。实时窗口的面板就摆在主画布左栏原来的位置（收起 0 宽、展开 364 宽、画布跟着让到右边），双击卡片展开；面板内容直接渲染主画布 `paintPanel` 那段模板，连「和它聊这张卡」一起搬，保存只写回这份解析结果；**卡片可拖，位置存进 `x/y` 且 layout 尊重手工坐标**，否则用户会说“没法拖动”或拖完又弹回去。
- 内容完整改动记一版，保留最近 20 版；位置/聊天/选择不成版。回滚也成版并使 agent 下次看到新版本事实。

完成标志：最小改动和自测范围清楚，不靠主管前置审批。交互读 `references/canvas-and-cards.md`；agent/实时读 `references/agents-and-live.md`；版本与预演读 `references/versioning-and-preview.md`。

### 3. 在隔离实例先给可见效果

通过 `terminal` 执行语法检查，并先显式确定测试端口、唯一数据目录与真假数据源：

```bash
node --check main.js
node --check renderer/app.js
node --check renderer/live.js
export CDP_PORT=9333
export WF_TEST_DATA="<本会话新建的隔离数据目录>"
```

用 `terminal(background=true)` 启动，真实数据模式显式去掉样本源变量：

```bash
env -u WF_LIVE_DIR ./node_modules/.bin/electron . --remote-debugging-port=$CDP_PORT --user-data-dir="$WF_TEST_DATA"
```

样本模式显式设置自己的 `WF_LIVE_DIR`；不要依赖前次 shell 环境。不得复用或清空用户数据目录。主进程和渲染脚本不保证热加载，取证前核实例对应的新代码。

完成标志：真实业务全图/必要局部图能说明方向；标待验，先亲眼看业务含义、模块、关系、关键文字与重叠，再跑长回归。不让长报告挡住第一次可见结果。

### 4. 以版本绑定证据并独立验收

按当前仓库实际脚本运行需要的语法、纯函数、交互和旧功能检查；修改协议时同步断言，但不为凑通过放宽业务标准。

- 无模型检查优先：已有拆卡/样本脚本和独立关系用例。
- 真调用注明实际耗时与工具调用，不重复挑一张成功截图冒充稳定。
- 异常引用、循环与历史缺口必须被拒绝或明确标记；布局应有界，不能把反馈回指喂成无限深度。
- 检查原始响应、字段保留、卡面和真实关系，不只数节点/边。
- 改完解析或布局后重取对应测试和图；最后一笔未验就直接写未验。
- 独立验收由当前授权的验收角色对最终 commit 执行，不能由实现方自测或证据准备替代。

完成标志：改动文件与字节、原始命令结果、截图、未解决项和对应 HEAD 一致；证据放正确的私有/公开位置。汇报只答能不能用、证据、需用户决定的事项。估时区分可看、交验、验收和落地，不凭 running 猜倒计时。

### 5. 安全收口与公开交付

仅在当前授权及独立验收满足后收口；先核在用副本与远端真实状态，再快进合并验收绑定的提交。保护在用工作区和用户窗口，合并代码不代表用户已打开新版。

公开前通过 `terminal` 执行产品扫描并核被跟踪对象：

```bash
node tools/scan-public.js
git ls-files -s
git ls-remote --heads origin
```

核密钥、本机路径、其他业务内容和 120000 符号链接目标；不只扫普通文件。公开图片/GIF也要亲眼检查。未获授权不提交/推送；改写已公开历史和强推必须另获用户明确批准，审批失败不换写法绕过。

完成标志：验收版本、合并内容与批准发布范围一致，外部写入已回读；未做的步骤不写完成。

## 从 Hermes desktop 打开（唤起）

- **窗内入口是右栏列表的第一行。** 实时入口不只放 ⋯ 菜单：右栏链路列表**第一行**就是「实时工作流」，和已存工作流并列（虚线边表示它不是一条已存链路、不进版本）。点它＝把**画布区**切换成实时视图——不是新窗口，也不是盖住整个工作台的浮层；顶栏名字变「实时工作流」、执行方下拉隐藏、其它工作流行让出选中态；点回任意工作流就自动退出并恢复名字与下拉。这就是用户验收这一项的原话标准：「像隔板 / 新工作流那样切换」。
- 已登记自定义协议 `workflow-studio://`：`open "workflow-studio://open"` 开或前置主窗口，`open "workflow-studio://live"` 切到实时视图（视同点右栏那张虚线卡）；`./node_modules/.bin/electron . --unregister-protocol` 启动一次即解除登记。
- 单实例靠 `app.requestSingleInstanceLock()`：第二个进程直接退出，把 URL 交给已开的那个窗口处理；实测连续唤起两次，进程数仍为 1、页面 1→2。
- **要打开用户平时用的那个实例（带 9222 调试口），跑仓库根的启动脚本**：`cd "<本机仓库根>" && (./打开工作流开发平台.command > /tmp/wf-launch.log 2>&1 &)`，然后 `curl -s http://127.0.0.1:9222/json/list` 确认有 `type=page`、title 为「工作流开发平台」，再用 `osascript -e 'tell application "System Events" to tell process "Electron" to get {position of window 1, size of window 1}'` 核到 1380×880。协议唤起只负责「开或前置」，它经 LaunchServices 起的是**不带调试口**的裸 Electron（窗口还会以 960×648 出现，低于应用自己的 minWidth），要 CDP 或要用户那套数据就必须走启动脚本。切换实例前先 `osascript -e 'tell application "Electron" to quit'` 退干净：单实例锁会让后起的进程把 URL 交给旧实例直接退出，端口依旧不会出现。
- **这个应用本身跨平台，别把它说成 mac 专属。** 被问到能不能上 Windows/Linux 时按代码回答：依赖只有 electron、路径全走 `os.homedir()`、快捷键判 `metaKey || ctrlKey`、`window-all-closed` 已按平台分支；真正 mac 专属只有五处——`打开工作流开发平台.command` 启动脚本、`main.js` 里 `~/.hermes/hermes-agent/.hermes/bin/hermes` 的 `execFile`（Windows 上是 `hermes.cmd`，`execFile` 不认）、`livefeed.js` 的 `/usr/bin/sqlite3` 兜底（Windows 默认没有）、提示文案里的 `⌘Z`、Linux 上 `workflow-studio://` 要先打包并装 `.desktop` 才生效。
- **Hermes desktop 聊天只放行 http/https/mailto**（`apps/desktop/electron/external-open.ts` 的 `SUPPORTED_WEB`），贴自定义协议链接点了会被自己拦掉——要唤起就让 agent 跑 `open`，别做聊天里可点的链接。

## Pitfalls

- **改卡面/预览先用保存过的解析结果重放，不重跑模型。** 一次解析 30–45 秒，为看一眼样式又跑一遍是纯浪费，用户会直接问「你怎么老是要重跑链路啊」；渲染层留一个只读重放入口（把 `live/<profile>__<session>.json` 喂给渲染函数），只有在协议/取料变了或用户点「重新生成」时才真调。真要造数据也只跑一次，之后反复用它。
- **自动行为先问自己「用户没点这个动作，为什么它会自己跑」。** 开关、跟随、重新解析、自动采用都容易变成「一打开就白跑一次」或「自己改了自己」：跟随只读消息与更新状态，解析/生成/应用只由人点按钮触发；已保存的结果重开直接展示，新的失败就保留旧的。
- **把用户的「不满意再重新生成」做成状态，不是做成提示。** 成功一次就落盘（按对象分文件、临时文件+改名）、重开即显示、按钮变「重新生成」；只有新的成功才替换旧的。
- **合并/改完不等于用户看到了新版。** 主进程和渲染脚本都不热加载；默认不碰用户窗口，只有用户说「开启一下 / 重开」才重启：按端口精确取 PID 停（`ps -Ao pid,command | grep "[E]lectron . --remote-debugging-port=9222"`），再用启动脚本重开，然后**断言新元素存在 + 一张截图**再说「现在是新版」；不能凭提交号或「已合并」宣布界面已更新。
- **「编辑工作流」（原名「确定工作流」）＝复制一份可编辑的 + 原图退成只读参考，不是原地解锁编辑。** 点一下要同时做到：深拷贝成一条新工作流（名字沿用原名、节点标 `manual` 保住解析时的位置；点「保留」那一步才在名字后加 `· vN`，不要用「已确定」这种后缀）、画布**上下**分屏（**上半 `#liveView` 只读参考、下半 `#wrap` 可编辑**，`.liveview{top:0;bottom:50%}`、`#wrap{inset:50% 0 0 0}`）、只读侧靠 `pointer-events:none` + 短路 ⌘Z/⌘S/Delete + `persist()` 不写三层挡住。**分屏方向别自己定：用户说的是「横向分开」，就是上下切、不是左右并排；位置以「参考在上、可编辑在下」为准（他最初让新画布在下，随后明确要求两块对调）。** 缩放条要跟着挪进可编辑那半（`bottom:14px`），否则会浮在参考区上。`fitView` 必须等分屏之后下一帧再跑：分屏前 `#wrap` 还是 `display:none`、尺寸为 0，先算会把缩放压到下限、下半看着是空的（半屏更矮，允许 `fitView(true, 0.2)` 低于常规 0.3 才能一眼看全）。实现与验据见 `references/canvas-and-cards.md` 的「编辑工作流」。
- **可编辑那半区要给「保留工作流」和「AI 补全」两个动作，别让用户自己找保存入口。** 保留＝把参考框内容搬到 `body`、**只有这一步才 `commitVersion(w)`**（名字写成 `基名 · v${w.version}`，**版本号只有 `w.version` 一个来源**：名字尾巴、列表副标题、版本项全读它；留着 `round` 另算会出现「名字 v6 / 版本 v31」，用户会直接说版本号对不上。`loadStore()` 收尾和切换工作流时用 `syncNameVersion()` 就地校正历史错位，只改名字不记版本），状态条回报时间与「几张卡的内容已转到上方」。`saveStore()` 只落本地存储 + 同步共享状态，**不再自动成版**——用户口径是「只有我点了保存/保留才算一个版本」；拖动、改字、AI 补全都不该凭空多一版。保存前先 `versionList` 拉一次已有版本，避免新版本号与既有版本撞号；**保留按钮永远只做保存一件事**，不要再在「保留工作流 / 继续编辑」之间换文案（用户原话：这两个重复了）；正常画布上点它也是存一版。想再进编辑点旁边那颗「编辑工作流」。AI 补全**严格按用户现有结构**：不增卡、不删卡、不动连线（prompt 里把已有 id 全列出来，只认这些 id，返回的新 id 一律丢弃；返回里没有的卡原样保留）；**输出卡与输入卡不许新增任何元素**（mods 只能在原有条目里改写措辞），**只有加工卡可以补工具/模型**；**prompt 里不要放旧 `body`**——只给「类型 / 标题 / 工具元素 / 我写的参考 / 它在链路里的位置」，明确要求重新写描述，否则模型会照着旧实例描述续写。结果在编辑态写进 `note` 供人复核，点保留才上移成 `body`。解析失败/无卡/抛错一律只回一句状态、不动原图。
- **解析模型输出成 JSON 前必须先 `agentAnswer(r.text)`。** `hermes -p <profile> chat -q` 的 stdout 会先回显 `Query: <提问原文>`，而提问里通常就带着 JSON 模板（schema 示例），直接取第一个 `{` 会解析到回显里的模板、报「不是合法 JSON」；尾部还有 `Resume this session with …` 会话块，也要切掉。
- **会写用户数据的交互（编辑工作流、保留、AI 补全）默认在隔离实例上测，别拿用户的 9222 窗口当试验田。** 在用户窗口里跑这类探针，每点一次都会往 localStorage 的 `store.workflows` 里塞副本；更要命的是「跑完按特征批量清理」会把用户刚建的工作流一起删掉（一条按 `fromLive` 过滤的清理脚本就删掉过用户 10 分钟前刚建的链路），用户当场看不见自己那条图。真要在这里测：先复制一份做靶子、只删自己建的那条 `id`，绝不批量过滤；收尾断言列表行数回到测试前数目，分屏还开着就点一行已有工作流退出。删错了立刻从版本库救：`~/Library/Application Support/workflow-studio/versions/<id>.json` 的 `list[].snapshot` 存着每一版的完整流程（`{name,agent,cards,edges}`），取出事发前那一版**按原 id** 写回 `store.workflows`、`saveLocal()` 而不是 `saveStore()`（免得又压一版），再删掉自己的测试副本。
- **测试靶子按 id 取，别按列表行号取。** `duplicateWorkflow` 把副本插在原行之后，`#wfList .wf` 第 0 行仍然是你那条真实工作流——「复制一份再拿第一行当靶子」会一头扎进用户数据里，改完还点了保留。取靶子用 `store.workflows.find(w => w.id === <刚建的 id>)`，收尾也按 id 删。
- **验证界面改动先开隔离实例，别反复退出重开用户的 9222 窗口。** 用户常常正在同一个窗口里改东西：一次会话里连着重启五六次既打断他，也让你「测试前记下的名字/版本」在测完时已经变了（他自己点了保留，名字从 v4 走到 v31），据此断言「你的数据没变」就会说错。渲染层改动在 9333/9335 的隔离实例（独立 `--remote-debugging-port` + 独立 `--user-data-dir`）里验；确实只能在大窗口看时，把改动攒成一批、只重启一次，收尾重新读一遍 `store.workflows` 的现况再汇报，别拿开头那份快照下结论。
- **AI 补全/通用化会把工作流改成它自己起的名字**，所以任何按名字后缀（如「· 已确定」）识别测试产物的脚本都会漏筛；识别测试产物只认自己写入的标记（`fromLive`、`pendingLive`）或记下的 id。
- **编辑态的卡片＝描述收起、底部一块「参考」框；保留时才把参考挪到上方。** 用户口径：进编辑后卡片不再显示原描述（`#canvas.editing .node .body{display:none}`），每张卡底部常驻 `.node .note` 文本框（默认隐藏，靠 `.editing` 类显现）供人写「这张卡要写清什么」；输入即写 `n.note` + `saveLocal()`。**参考框别放进 `nodeSig`，也别按模式重建节点**，否则每敲一个字整卡重建、光标丢；常驻 DOM、只切类即可（进出编辑态再 `layoutChain + render` 一次，因为卡片高度变了）。点「保留工作流」＝`note → body`（描述回到上方，和读取链路得到的卡一致）、清空 note、退出编辑态，按钮文案不变，想再进编辑点「编辑工作流」；编辑态点 AI 补全只写 note、不动 body。
- **「保留」才算数：编辑副本先进 `pendingLive`，不进历史列表。** 点「编辑工作流」只建草稿（`pendingLive: true`），`renderWorkflowList` 跳过它；点「保留工作流」才删标记、出现在「历史工作流」里；没保留就退出实时视图（`exitLive`）要把这些草稿从 `store.workflows` 里清掉并把 `store.current` 指回第一条。右栏还要分组：实时入口单独一栏（`#liveSlot`，小标题「实时 · 正在跑」），已存工作流在 `#wfList`（「历史工作流」），别混在一列里。
- **历史工作流也能进同一套编辑：顶栏「编辑工作流」按钮 + 右栏每行 `✎`。** 两个入口同一实现（`editHistoryFlow(id)`）：点它把**这一版**做成只读快照、`enterSplitRef()` 进同一套上下分屏，上面参考、下面是同一条工作流的可编辑态；「保留」是**升级这一条**（名字带 vN），不产生副本。按钮在实时视图里隐藏、进入分屏后也隐藏（避免重复进），退出分屏要恢复显示。参考视图复用实时那块 `<webview>`：`src='live.html?mode=ref'`，`live.js` 里用 `location.search` 判 `mode=ref` 时只做 `bindCanvas` + 等 `ref:doc`、渲染后 `setReadOnly(true)`，`body` 加 `refmode` 藏掉解析/跟随/撤销控件并把品牌改成「参考 · 只读」；`preload.js` 加 `onRefDoc`（监听 `ref:doc`），主窗口用 `wv.send('ref:doc', snapshot)` 灌快照。参考里的卡 `openCard` 走只读预览（类型/标题/描述/元素/impl），**双击能看元素但不改**。在实时分屏与历史编辑之间切换时先把 `src` 指回 `live.html`，否则一直停在参考视图。
- **一条工作流＝一个项目文件夹，右栏行内展开它的各个版本。** 行**右下角**的「▸ 版本 / ▾ 版本」胶囊展开（点副标题那一行也行；放右上会压住标题，用户会要求挪到卡片右下角并给副标题留 `padding-right`），版本行 `vN · 时间 · 改了什么` + **「编辑」「恢复」**（`tcflow.versionList(id)`，缓存 `verCache`、展开态 `openVers`）。**存完必须 `delete verCache[w.id]` + `openVers.add(w.id)` + 延迟 200ms `loadVersions()`**，否则用户「保存了之后看不到历史版本」。**编辑**＝先把该版 `snapshot`（`{name,agent,cards,edges}`）载入当前项目（只 `saveLocal()`、不记版本），再 `editHistoryFlow()` 进分屏——上面就是这一版的只读参考；**恢复**＝只把内容换回该版，同样不记版本；要留痕都靠之后点「保留工作流」。不要在画布里另造一个「版本只读视图」——用户要的是文件夹里存版本，不是再一套渲染态。
- **画布操作条常驻三颗：编辑工作流 / 保留工作流 / AI 补全（另加 ↶ ↷）。** 放在画布右上 `#actBar`，实时视图里整条隐藏（那边用自己的按钮），进分屏后挪到下半区顶部并隐藏「编辑工作流」。别把「保留」「AI 补全」只藏在分屏里——用户会要求「画布里同时有这三个」。
- **编辑态左下要有整条工作流的需求框。** `<textarea>` 存 `w.req`（`saveLocal()`，不进版本），AI 补全的提示词里作为「我的总体要求（优先满足）」放在链路清单之前；只影响措辞与加工卡工具、不改结构。需求框只在编辑态显示（`.canvaswrap.live.split .reqbox{display:flex}`），并提供一颗「按这段要求补全」直接触发。 快照（`{name,nodes,edges}`）里已经带着坐标，`applyEditSnap` 里若再调 `layoutChain`，会把卡按链重排——实测撤销后卡片直接跑到画外，用户以为数据丢了。撤销/重做的入口也搬进编辑那半区（操作条 `↶ ↷` + ⌘Z/⇧⌘Z/⌘Y，焦点在输入框时让给浏览器原生撤销），实时那半边只读后把它自己的撤销/保存按钮藏掉，别让人以为能在参考区改。
- 用户说不像已有卡片时，先查语义、粒度和字段，不先调颜色或另加点评按钮。
- **用户说「以 X 为准」就是让你删掉自创那套，不是再对照一遍。** 两套并存时他每轮都会看见差别、每次要求返工；动手时先把自创的卡种、边类型和徽标删掉，再把提示词、解析器和卡面三段对齐已认可那套。
- **对齐的验据要落到内容层。** 逐卡看类型/标题/正文/模块三段；DOM 断言用加工卡的模块行数、正文正则（无路径、无命令、无 JSON）、卡片重叠 0。class 相同或截图好看都不算统一。
- **两个界面要对齐时，搬源码里那段模板，别照着重写。** 目标窗口要有和主画布同一张卡/同一个面板时，把源实现（`renderer/app.js` 的 `paintPanel` 模板字符串）整段取出来复用，只删目标真没有的块（聊天、预演），id、class、字段顺序原样保留；自己重写一遍必然缺字段、错 class、样式对不上，用户会直接问「你不能直接读源码复制过去么」。拼接后立刻 `node --check`：模板里有嵌套反引号和 `${}`，切片或包裹差一点就是语法错；并在源码处写一句「这里改了要同步搬」，避免两处分叉。
- **「完整照搬」＝把那段代码抽成两个窗口共用的模块，不是再抄一份。** 用户说「拖动这些代码也是」，就是元素级一致不够、行为也得同源：把源窗口的 `nodeEl` / `modsHTML` / `chipHTML` / `drawEdges` / `dragCard` **以及排版函数 `layoutChain`** 整段切进共享脚本（本仓 `renderer/cardsys.js`，两个页面都在各自主脚本之前引入），新宿主只提供适配器 `flow()`（把本宿主的 doc 映射成 `{nodes, edges}`，边只保留两端）、`find()`、`saveStore()`、`openCard()`、`chatAsk()`、`markSel()`、`unplugDrag()`、`findDock()`（恒返回 null）、`startLink()`（覆盖成只提示只读）。缺任何一个适配器，搬来的 `pointerdown` 第一行 `markSel()` 就抛 ReferenceError，表现是「卡能看不能拖」且控制台安静。抽完在源文件写一句「这里改了要同步搬」，否则两个窗口再次分叉。
- **排版不搬＝没搬。** 只把卡片外壳和拖动搬过去、排布仍用自己写的算法，列宽/间距/竖向居中一不同，用户第一眼就是「为什么你照搬都没有搬好」。判断对齐的标准是排布规则同源（同一个 `layoutChain`），不是卡片长得像。
- **共享脚本的适配器用 `function` 声明，不要用 `const`。** 两个经典脚本共享全局作用域：宿主里的 `const findDock = () => null` 与共享脚本的 `function findDock()` 撞成 `Identifier 'findDock' has already been declared`，宿主脚本整份不执行——症状是共享函数都存在、宿主自己的函数全是 `undefined`、界面空白而控制台只有一条 SyntaxError。函数声明同名才是「后者覆盖前者」。
- **打开是空白时先查「视野里有没有卡」而不是「卡有没有生成」。** 卡画在 `ORIGIN` 偏移之后的坐标上，若 `fit()` 没执行，`wrap.scrollLeft` 仍是 0，卡片全在 6000px 之外：`nodes=8` 但 `visible=0`，看起来就是空画布。渲染完必须 `requestAnimationFrame` 里再 `fit()` 一次（布局尺寸要等一帧才准），验收断言用「卡片 rect 与视口相交的数量」，不用卡片总数。
- **「跳画布 / 找不到工作流」先查视野两件事：更新后是否重排又 `fit()`，以及缩放后的滚动区是否仍是未缩放尺寸。** 前者用「锚定视口中心那张卡」修（更新前记它的屏幕 rect，排版后把差值补回滚动），后者用「滚动夹紧到内容包围盒」修（`transform: scale()` 不改滚动区，缩小后能滚进大片空白）。公式、挂载点与验据见 `references/canvas-and-cards.md` 的「视野锚定与边界」。
- **连线的弯法只在结构变化时算一次，拖动时不许按中点重算。** 拖动每帧都会 `drawEdges()`；控制点若每次取 `(x1+x2)/2`，曲率就跟着手指连续变，用户会直接要求「拖动后不要再重新计算线的曲度」。每条边缓存一个控制点水平偏移（`EDGE_DX["a>b"]`），拖动只平移/拉长端点；只在 `layoutChain` 收尾、新建连线、导入/换工作流时带 `{recalc:true}` 重算，并顺手删掉已不存在边的缓存。公式与验据见 `references/canvas-and-cards.md` 的「连线曲率」。
- **改共享脚本里某个函数前，先 `grep -c "function <名>"` 查重复定义。** 从源页面整段抽函数时很容易把同一段抽两遍（文件里两个 `drawEdges`、两个 `peer`），后者静默覆盖前者——你改的是死的那份，改完「没效果」且语法检查照样通过。先删重复再改，`node --check` 之后再用 `grep -n` 确认只剩一份。
- **适配器要对缺字段的老存档容错。** 旧 JSON 可能没有 `conv`：`flow()` 里直接取 `doc.conv.key` 会抛错，而抛错点在节点已追加之后，于是排版、连线、对焦全部被跳过——用户看到的是「卡歪在一边/一片空白」，不是报错。`flow()` 用 `(doc.conv && doc.conv.key) || doc.name || 'live'`，状态栏也按卡数兜底。
- **只读/对齐窗口的「拖了又弹回」只从两处来：拖动不落盘、自动排版盖掉手工坐标。** 拖动松手先写 `n.manual = true` 再存盘，`layout()` 只给 `manual` 为假的卡重算坐标；否则用户拖完一松手、下一次重排就弹回原位。
- **对齐一个面板＝位置、宽度行为和全部区块一起对齐，不只是字段。** 字段搬齐了用户仍会说「这也不一样啊，位置，还有 agent 也没有」：照抄源面板所在的那一栏（左栏、展开 364px、收起零宽 + `transition`，画布用 flex 让位），聊天区也算「同一张卡」的一部分，不能因为目标窗口用不上就删掉再解释。搬聊天块时把「和谁聊」换成被观察对象自己的显示名，发送走 `askAgent(profile=<被观察岗位>)`，气泡按 `role: me/agent` 存进这张卡并随解析结果落盘；每次发送是一次真实调用，只由用户点发送触发。
- **悬停提示别用原生 `title`。** 系统提示要等约一秒、长内容会被截断、也跟着指针不动；用户说的「移上去能看具体是啥」默认就该快且完整——chip 挂 `data-tip`，`mouseover/mousemove` 驱动一个 `position:fixed` 浮层，按指针坐标定位并夹进视口，离开/滚动/失焦收起，`title` 只留兜底。明细取来源卡自己的 impl（带路径或数字的那行），不重复卡面正文。
- **实时视图要就地内嵌，不再开第二个窗口；三处必须一起改。** 主窗口开 `webviewTag: true`，容器放进画布区（`.canvaswrap` 加 `position:relative`，视图 `position:absolute; inset:0`），用状态类 `.canvaswrap.live` 显示它并隐藏画布自带的缩放条/停靠对话/空态按钮；`<webview>` 的 `preload` 属性只认绝对路径，而沙箱 preload 里拿不到 `__dirname`（表现是 `window.tcflow.appDir` 为 undefined、整段 `showLiveView()` 直接抛错），要从一个 `app:dir` IPC 取目录；主进程原先认 `BrowserWindow` 的地方改认 `webContents`：`dom-ready` 时上报 `getWebContentsId()`，主进程 `webContents.fromId(id)` 存成 `LIVE.wc`，推送改 `LIVE.wc.send(...)`，`destroyed` 时清空并停轮询。入口（顶栏按钮 / 右栏虚线卡 / 协议）统一走「focusMain + `webContents.send('live:show')`」，别再建窗。
- **「像 X 那样切换」＝并进已有导航的同一处，不是另做一层浮层。** 用户拿现有工作流当参照时（「像隔板 / 新工作流那样切换」），先看参照本身怎么被选中：列表里的一行 + 同一块内容区 + 选中态互斥。做成整窗浮层、独立窗口或加一条返回栏都算没做到——即使已经不开新窗口，用户仍会说「不是这个意思」。落实要同时改三处：列表渲染里把这一行插在最前（`renderWorkflowList` 前置，`liveMode` 为真时其它行不再高亮、顶栏名字改只读）、内容区靠状态类切换、列表点击与 `switchWorkflow()` 互相退出。验收断言：进入后只亮一行、画布区尺寸等于原画布区（不是整窗）、点回工作流后 `canvaswrap` 类名与名字都恢复。
- **探针认目标别只认 `page`，模拟拖动要带 `buttons: 1`。** 内嵌 `<webview>` 在 CDP 里是独立目标、`type` 为 `webview`，按 `type === 'page'` 过滤会得到「没有这个窗口」，看着像视图没起来；拖动是 `mousePressed` → 多次 `mouseMoved`（每个都要 `buttons: 1`，否则页面收不到拖动中的 pointermove，表现成「拖不动」）→ `mouseReleased`，双击要选一个 rect 落在视口内的卡，别拿第一张。**编辑态要抓卡片头部**（`rect.top + 18`）：卡片中心此刻多半是底部那块 `.note` 输入框，它 `stopPropagation` 掉 pointerdown，结果是拖不动、撤销也不亮——先换落点，别改产品代码。
- **同目录名、相同函数名或相似提示词不证明两条入口共用分析**；逐层追一次真实样张。
- 只读不等于可以省略素材/成果，结构连通不等于依赖真实。
- CDP 探针必须自包含、判空、render 后重新取元素；异步表达式用 IIFE，点击用真实鼠标事件。
- **探针别用 `node -e` 拼内联表达式。** 表达式里有反引号、`${}`、中文和引号时，shell 转义迟早出错，报的是 `SyntaxError: Invalid or unexpected token` / `unexpected EOF`，看起来像产品 bug。把表达式写成文件，用一个固定脚本连 CDP 执行（本仓 `skills/workflow-studio/scripts/cdp-eval.js --port 9335 --page live.html --expr-file x.js`）。
- **`git commit --amend` 前先 `git log -1 --name-only` 确认 HEAD 就是那条要改的提交。** 连着提交 fix 和 docs 时最容易改错：amend 会把后一条并进前一条的消息里，同一条修复出现两次、另一条变更被吃掉。发现后 `git reset --soft <基线>`、再按文件分两次重提，别在同一 HEAD 上反复 amend。
- **用脚本做整段替换后先查重复声明再做语法检查。** 同一脚本里对同一标识符二次声明（`let saveTimer` 加了两遍）只会得到一条 SyntaxError，整个文件静默不执行；替换后 `grep -n "let <名>\|function <名>" <文件>` 再 `node --check`，不要只信 `--check` 通过就以为没重影。
- 流中整块 innerHTML 重建会丢折叠态和点击；只更新变化节点。
- 图与测试对应哪个版本写清；未验收的实验解析/布局不能写进手册当可靠方法。
